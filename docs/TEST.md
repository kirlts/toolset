# Testing Strategy

> Generated by `/test` (Mode 1). Testing contract for Toolset Personal — infraestructura, ops, CI/CD.

## Testing Stack

| Layer | Runner | Justification |
|---|---|---|
| Static analysis | `shell -n`, `python3 -m py_compile` | Scripts de deploy y provisioning sin test runtime |
| Validation scripts | Python CLI + bash | Verificacion de schemas JSON, YAML parse, Infisical reachability |
| Integration checks | `preflight.sh` existente + `test-tenant.sh` nuevo | Ejecutables contra el VPS post-deploy |
| Manual verification | Procedimientos descritos en esta tabla | Operaciones que requieren WhatsApp pairing o GitHub UI |

## Automatic Triggers

| Trigger | Subset to execute |
|---|---|
| Modificacion de `infrastructure/deploy.sh` | `test-deploy-syntax`, `test-tenant-sync` |
| Modificacion de `infrastructure/hermes/scripts/provision-tenant.sh` | `test-provision-syntax`, `test-validator` |
| Modificacion de `infrastructure/hermes-skills/tenant-grupo/` | `test-skill-manifest` |
| Modificacion de templates de tenant (`tenants/template/`) | `test-template-placeholders` |
| Creacion de nuevo tenant | Suite completa de tenant (`test-tenant-*`) |
| Push a main que toca `infrastructure/hermes/` | `preflight.sh` + `test-deploy-syntax` |

## High Priority Tests (Inviolable Boundaries)

| ID | Description | Verifier | Command |
|---|---|---|---|
| HP-001 | deploy.sh pasa validacion de sintaxis bash. Sin errores de comillas, pipes, o heredocs | .LLM | `bash -n infrastructure/deploy.sh` |
| HP-002 | provision-tenant.sh pasa validacion de sintaxis bash | .LLM | `bash -n infrastructure/hermes/scripts/provision-tenant.sh` |
| HP-003 | validate-tenant-json.py detecta JSONs invalidos: nombres reservados, toolsets prohibidos, memory provider incorrecto | .LLM | `python3 infrastructure/hermes/scripts/validate-tenant-json.py infrastructure/hermes/tenants/definitions/<tenant>.json` |
| HP-004 | Un tenant NO puede acceder a `~/.hermes/` del Hermes main | .HUM | `sudo -u opc test -r ~/.hermes/.env && echo "FAIL" || echo "PASS"` desde el contexto del tenant |
| HP-005 | Un tenant NO tiene acceso a Hindsight MCP (no debe haber `hindsight-selfhosted` en su config.yaml) | .LLM | `grep -q "hindsight" ~/.hermes/profiles/<tenant>/config.yaml && echo "FAIL" || echo "PASS"` |
| HP-006 | `WHATSAPP_ALLOWED_USERS` del tenant bloquea numeros no autorizados en el gateway | .HUM | Enviar mensaje desde numero no autorizado al tenant. Debe ser rechazado (sin respuesta). |
| HP-007 | sync-hermes-to-repo.sh backupea whatsapp-groups.yaml de tenants al repo | .LLM | `test -f infrastructure/hermes/tenants/backups/<tenant>/whatsapp-groups.yaml` post-sync |

| HP-010 | Infisical expone secrets de tenant via `localhost:8080` | .LLM | `curl -sf localhost:8080/api/v3/secrets?path=/tenants/<tenant>/` retorna JSON con secrets |

## E2E Policy

- **Activado cuando:** Se crea un tenant nuevo o se modifica `provision-tenant.sh`
- **Prevencion:** El pairing de WhatsApp requiere QR (manual). El deploy key de GitHub requiere UI (manual). El resto del flujo E2E es automatizable.
- **Scope:** `create → validate → provision → gateway start → CI/CD backup → simulate disaster → restore → verify`

## Tenant Test Suite (`test-tenant.sh` — nuevo, a crear en VPS)

Script ejecutable desde el VPS que valida un tenant completo:

```bash
#!/usr/bin/env bash
# test-tenant.sh <tenant-name>
# Validacion post-provision de un tenant Hermes.
set -euo pipefail
TENANT="$1"; PROFILE="$HOME/.hermes/profiles/$TENANT"
echo "=== Tenant Test Suite: $TENANT ==="

# 1. Profile directory exists
[ -d "$PROFILE" ] && echo "PASS: profile dir" || { echo "FAIL: profile dir"; exit 1; }

# 2. Config has holographic memory (not hindsight)
grep -q "holographic" "$PROFILE/config.yaml" && echo "PASS: memory=holographic" || echo "FAIL: memory not holographic"
! grep -q "hindsight" "$PROFILE/config.yaml" && echo "PASS: no hindsight MCP" || echo "FAIL: hindsight found"

# 3. Toolsets are restricted (no docker, no systemctl)
grep -q "docker" "$PROFILE/config.yaml" && echo "FAIL: docker in toolsets" || echo "PASS: no docker"
grep -q "systemctl" "$PROFILE/config.yaml" && echo "FAIL: systemctl in toolsets" || echo "PASS: no systemctl"

# 4. .env exists and has required vars
grep -q "WHATSAPP_BOT_NUMBER" "$PROFILE/.env" && echo "PASS: WHATSAPP_BOT_NUMBER" || echo "FAIL: missing WHATSAPP_BOT_NUMBER"
grep -q "WHATSAPP_ALLOWED_USERS" "$PROFILE/.env" && echo "PASS: WHATSAPP_ALLOWED_USERS" || echo "FAIL: missing WHATSAPP_ALLOWED_USERS"

# 5. SOUL.md mentions the tenant name
grep -q "$TENANT" "$PROFILE/SOUL.md" && echo "PASS: SOUL.md identity" || echo "FAIL: SOUL.md missing identity"

# 6. Tenant marker exists
[ -f "$PROFILE/.tenant" ] && echo "PASS: .tenant marker" || echo "FAIL: no .tenant marker"

# 7. Workspace dir exists
[ -d "/home/opc/workspace/tenants/$TENANT/repos" ] && echo "PASS: workspace" || echo "FAIL: workspace missing"

# 8. Backup file in repo (if sync-hermes-to-repo.sh has run)
BACKUP="infrastructure/hermes/tenants/backups/$TENANT/whatsapp-groups.yaml"
[ -f "/opt/toolset-repo/$BACKUP" ] && echo "PASS: CI/CD backup exists" || echo "INFO: CI/CD backup not yet synced (normal if cron hasn't run)"

# 9. Infisical secrets reachable
curl -sf "localhost:8080/api/v3/secrets?path=/tenants/$TENANT/" > /dev/null 2>&1 && echo "PASS: Infisical secrets" || echo "WARN: Infisical check skipped (no token)"

echo "=== Suite complete ==="
```

## Ejecucion automatica post-deploy

Agregar al final de `deploy.sh` (o dentro del tenant sync block):

```bash
# Run tenant test suite for each tenant
for tenant_json in "$TENANTS_DEF_DIR"/*.json; do
  TENANT_NAME=$(python3 -c "import json; print(json.load(open('$tenant_json'))['name'])" 2>/dev/null || echo "")
  [ -z "$TENANT_NAME" ] && continue
  echo "  Testing tenant '$TENANT_NAME'..."
  ssh "${SSH_HOST}" "bash /home/opc/.hermes/scripts/test-tenant.sh $TENANT_NAME" 2>&1 | sed "s/^/  [test-$TENANT_NAME] /" || echo "  ⚠ Some tests failed for $TENANT_NAME"
done
```
